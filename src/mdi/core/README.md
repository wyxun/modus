# MDI core：公共契约层

`core/` 是芯片无关的公共层。这里定义资源 token 展开规则、状态码、类型化帧、能力
标记和绑定模板；这里不能包含厂商 CMSIS 头文件、板卡名称、外设编号或具体引脚。

## 文件职责

- `contract.h`：应用可见的 `MDI_*` 调用形态、数据类型和状态语义。
- `timer.h`：可配置外设定时器的启动、停止、频率和运行状态契约。
- `tick.h`：无单位 raw tick 读取和按调用点保存基准的周期判断宏；不做时间单位换算。
- `bind.h`：用 X-list 将寄存器表达式绑定成 `static inline` 采样/PWM 操作。
- `adc.h`：最基本的单通道 ADC code 读取契约；不规定扫描、DMA 或滤波方式。
- `stream.h`：通用字节流读写、可读数量和忙状态契约；provider 自己决定缓冲、调度
  与流控方式。

`core/` 不为具体应用提供配置表或策略接口。比如“每个 ADC 通道采样多少次”、DMA
缓冲区如何分段、均值或 IIR 如何计算，都不是 core 的职责；这些内容必须由 feature 的
绑定参数或芯片实例表达。这样三相 FOC、母线监测和温度采样可以共享同一套基础契约，
又不会把某一种采样流程固化成所有芯片都必须实现的公共接口。

板级维护回调 `mdi_Init()`、`mdi_Service()` 和 `mdi_Clock()` 也不属于 `core/`。它们由
MODUS 根接口声明并由各板 `peripheral/<chip>/mdi/service.c` 实现：`mdi_Init()` 承载一次性
状态准备，`mdi_Service()` 承载项目需要的前台硬件服务，`mdi_Clock()` 承载 1 ms 级轻量
维护。DMA/Stream 的共享缓冲和序号由同目录 `state.c` 定义，不能把这些板级状态偷偷变成
core 的运行时对象。

绑定宏生成的是类型和直接操作，不是描述符数组。资源 token 是预处理 token，例如
`bridge` 会展开成 `bridge_pwm_Stage()`；它不是运行时索引。

绑定宏不能用来掩盖运行时分派。实现评审必须继续追踪展开后的函数体：热路径不能
重新进入对象查找、`void *` 上下文、函数指针、虚表或通用命令分发。只有在预处理结果
和优化后汇编都确认是直接 provider 操作时，才能称为静态零抽象开销；“调用写成宏”
本身不是证据。

## 后端必须明确的约束

芯片绑定要同时说明寄存器所有权、单位、调用上下文、完成时刻和失败行为：

- 采样接口只读取已经完成的帧，不启动转换，不等待 ADC。
- `MDI_PWM_Stage` 做完整帧检查；`MDI_PWM_StageFast` 要求调用者已验证范围和更新窗口。
- `MDI_PWM_Commit` 只请求硬件提交，实际预装载和安全门控由后端配置。
- 总线 transfer 的缓冲区只在同步调用期间借用；异步/DMA 必须另定义生命周期契约。

如果一个资源不具备某项能力，不要提供返回 `MDI_OK` 的空实现。让接口在编译期不可见，
或返回明确的 `mdi_status_t` 错误。

新增功能的判断顺序是：先复用现有 core 原语；如果只是组合、调度、滤波、协议或设备
语义，放入 `feature/`；只有跨芯片且不可再拆分的硬件原语才进入 core。新增 core 后必须
同步更新静态绑定、负编译和调用开销验证。
